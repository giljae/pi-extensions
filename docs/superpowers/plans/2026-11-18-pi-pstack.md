# pi-pstack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `@giljae/pi-pstack`, a skills-only Pi package that mirrors Lauren Tan's `pstack` (`poteto-mode`, 24 principles, 34 workflow skills, two agents) on the repo's shared vendoring core, with a Pi harness adapter that maps Cursor names and a fail-loud transform set.

**Architecture:** A new descriptor at `scripts/vendors/pi-pstack.ts` pins a `cursor/plugins` commit, copies `pstack/skills` and `pstack/agents`, drops `statechart`'s test corpus via a new core `exclude` option, and applies two fail-loud transforms (`pi-host-note`, `pi-agent-frontmatter`). The package is skills-only; an authored `harness/pi.md` maps Cursor's `Task`, model slugs, and paths onto Pi. Milestone B (a later plan) adds optional `pi-subagents` delegation.

**Tech Stack:** Node 22+, npm workspaces, TypeScript (no build step), vitest, `@changesets/cli`, GitHub Actions.

**Spec:** `docs/designs/pi-pstack.md`

## Global Constraints

- Package name `@giljae/pi-pstack`; skills-only plus vendored `agents/`, no extension, no `dependencies`.
- Upstream: repo `https://github.com/cursor/plugins`, commit `93b916d4a1e806507e22f4716b352fa91f2b227e` (subtree `pstack/`). If executed much later, re-resolve the newest commit and record the new SHA in `UPSTREAM.json`; do not use a moving ref.
- Include `pstack/skills` → `skills` and `pstack/agents` → `agents`. Exclude `skills/statechart/scripts/test`.
- Transforms, both fail-loud: `pi-host-note` on `skills/*/SKILL.md`, `pi-agent-frontmatter` on `agents/*.md`. Never hand-edit the vendored tree.
- The Pi note line is exactly `` > On Pi, read `harness/pi.md` at this package's root before acting, and map every Cursor name it lists (`Task`, model slugs, `.cursor` paths) onto Pi. `` and its marker is `` read `harness/pi.md` ``.
- Cursor-only frontmatter keys to strip: `icon`, `color`, `alwaysApply`, `paths`.
- Manifest: `license: "MIT"`, a `repository` object with `directory: packages/pi-pstack` (npm provenance requires it), `publishConfig.access: "public"`, `files: ["skills", "agents", "harness", "README.md", "LICENSE"]`, `pi: { "skills": ["./skills"] }`, `keywords` includes `pi-package`.
- `LICENSE` carries upstream MIT text, Copyright (c) 2026 Lauren Tan.
- No workflow changes: `vendor-sync.yml` discovers `scripts/vendors/*.ts`; `release.yml` is package-agnostic.
- Version starts at `0.0.1`; the release is a `patch` changeset.
- Pi discovers skills as any directory containing `SKILL.md`; playbooks (`.md` without `SKILL.md`) are not skills. Pi has no built-in subagent; `pi-subagents` is optional and out of scope for this plan.

## Review Focus

1. **The excluded corpus must really be gone.** A stale copy or a partial exclude ships 3.6 MB and fails hashing. (Task 1 test, Task 5 integrity test)
2. **`pi-host-note` must be idempotent and anchored.** A second application or a missing frontmatter must throw, never double-inject. (Task 2)
3. **The strip must not touch prose.** `paths:`, `icon:`, etc. appearing after the frontmatter must survive; only the frontmatter body is rewritten. (Task 2)
4. **The agent without `model`/`is_background`.** `comment-sicko` has neither; the transform must still succeed and add `inheritSkills`. (Task 2)
5. **Every skill must reach the adapter.** Each `skills/*/SKILL.md` carries exactly one note and `harness/pi.md` exists with the mapping tables. (Task 4, Task 5)

- [ ] **Step 3: Implement `scripts/vendors/pi-pstack.ts`**

Follow `scripts/vendors/pi-postgres-skills.ts`. Shared helper (identical slicing to `pi-postgres-skills`):

```ts
function frontmatterEnd(text: string): number {
  if (!text.startsWith("---\n")) throw new Error("missing frontmatter");
  const close = text.indexOf("\n---", 4);
  if (close === -1) throw new Error("unterminated frontmatter");
  return close + "\n---".length;
}
const OPEN = "---\n".length;
const CLOSE = "\n---".length;
```

`piHostNote` (`name: "pi-host-note"`, `include: (relPath) => /^skills\/[^/]+\/SKILL\.md$/.test(relPath)`): throw if `text.includes(PI_NOTE_MARKER)`; compute `at = frontmatterEnd(text)`, `body = text.slice(OPEN, at - CLOSE)`; drop every line starting with `` `${key}:` `` for each of `icon`, `color`, `alwaysApply`, `paths`; rebuild `` `${text.slice(0, OPEN)}${kept}\n---` ``, then return `` `${head}\n\n${PI_NOTE}\n${text.slice(at)}` ``.

`piAgentFrontmatter` (`name: "pi-agent-frontmatter"`, `include: (relPath) => /^agents\/[^/]+\.md$/.test(relPath)`): throw if `text.includes("inheritSkills:")`; split the frontmatter the same way; if a line starts with `model:` and does not start with `model: claude-`, throw; drop the `is_background:` and `model:` lines; append `inheritSkills: false`, and append `thinking: high` when a `model:` line was present; return the rebuilt head plus `text.slice(at)`.

Constants:

```ts
const PI_NOTE_MARKER = "read `harness/pi.md`";
const PI_NOTE =
  "> On Pi, read `harness/pi.md` at this package's root before acting, and map " +
  "every Cursor name it lists (`Task`, model slugs, `.cursor` paths) onto Pi.";
```

- [ ] **Step 3: Write `harness/pi.md`**

Model it on upstream's `docs/harness/claude-code.md`. It must contain these tables (Cursor name → Pi):

- **Tools:** `Task` → `subagent` (or do the work in the main thread when no subagent tool is present); `AskQuestion` → ask in plain text; open a todolist / copy steps into the todolist → keep the list in the plan file or the reply; run another pstack skill → `read` its `SKILL.md`; `Grep`/`Glob` → `grep`/`find`.
- **Subagent fields:** `subagent_type: generalPurpose` → the closest built-in (`delegate`); `poteto-agent` / `comment-sicko` → `agent: "poteto-agent"` / `agent: "comment-sicko"` once registered with `pi-subagents`; a Cursor `model:` slug → omit it; `readonly: true` → an agent whose `tools` are read-only (`reviewer`); `run_in_background: true` → a background run; `environment: "cloud"` → a worktree, or skip when the cloud machine itself is needed.
- **Models:** a `claude-*` / `gemini-*` slug → the Pi session model by default, or a `pi-subagents` `thinking` level when `pi-subagents` is installed. Never pass a Cursor slug to a Pi tool.
- **Paths:** `.cursor/skills/`, `~/.cursor/skills/` → this package's `skills/`; `~/.cursor/rules/*.mdc` → `AGENTS.md`; transcripts under `~/.cursor/projects/<slug>/agent-transcripts/` → `~/.pi/agent/sessions/`; an upstream GitHub URL → the matching file in this package when it exists.
- **Cursor-only features:** Bugbot, Cursor Automations, cloud agents, and the built-in PR tool. When a step needs one, write one line, `` Skipped on Pi: <step>. <reason>. ``, then continue; do not stop or ask.
- **`setup-pstack`:** skip model pinning. Pi uses the session model; role-based model selection belongs to `pi-subagents` configuration in a later release.
